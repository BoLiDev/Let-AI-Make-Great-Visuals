# 审美偏好记录

仓库所有者的偏好，由评审反馈沉淀而来。做默认外观、模板和范例时以此为准。

## 原则

- **信息的暴露是有层次的**（2026-11-23）：不是暴露的信息越多越好。很多信息没有必要一开始就摆出来，读者在使用过程中会通过界面自然理解。一开始把所有东西摆到台面上会造成认知过载。落到做法上：
  - 首屏只放结论和最少的数字；细分数字放到悬停提示或下一层页面。
  - 图形只配读懂它所必需的最少说明（例如只标颜色含义的图例），不附带数字和补充解释。
  - 加任何一块信息前先问：读者不看它会损失什么。答不上来就不放。

- **报告是阅读材料，不是对话**（2026-11-23）：不要用整句话向读者叙述结论（例如"共 28 个问题，其中 3 个阻断级需要在下次发布前修复。"）。那是把页面当成一次对话在讲。阅读材料靠视觉层级让读者自己读：重要的数字放大、放前面、用颜色标出，而不是写进句子里。落到做法上：
  - 标题下面不放总结性的导语段落。
  - 结论用"标签 + 数字"呈现，关键项靠位置、字号和颜色突出。
  - 不出现"需要""建议""请"这类对读者说话的措辞。

## 内容

- **模板尽可能简单**（2026-11-23）：不要出现与上次扫描的对比（"上次扫描于""较上次""本次新增""已修复"这类）。只呈现这一次的结果。页面上也不显示扫描时间。

- **详情页不要臃肿**（2026-11-23）：详情页沿用列表页的版式（结论、一个概览面板、一个带搜索框的表格）。不要再加种类条形图、成排的筛选按钮、下拉筛选、每行第三层的附加信息。

- **分布条的图例只说明颜色，不带数字**（2026-11-23）：分布条下面保留一行图例（色块加"阻断 / 严重 / 一般 / 提示"），否则读者不知道颜色的含义。但不放分项数字和补充说明，数字在悬停各段时显示。

## 版式

- **喜欢 Moss / Onyx 这一套的版式**（2026-11-23，代码扫描报告预览第一轮）：大圆角、概览放在带底色的圆角面板里、分区不用粗线、胶囊形的筛选按钮和条形图。对应 Basecoat 的 Maia 风格加 `themes/moss.css` 里的结构变量。

- **占比条要是一整条**（2026-11-23）：堆叠的占比条应是一个完整的条形，各段首尾相接、中间不留缝，圆角只出现在整条的两端。不要做成几个各自带圆角的小段。

- **可点击的行不用箭头图标表示**（2026-11-23）：不要在行尾放 chevron。用标题本身（链接样式）和悬停时整行背景变灰来表达可点击。

## 配色

- **深色主题的一般偏好**：黑白灰为底，绿色和浅红作为仅有的两种彩色（所有者在 OKX 工作，习惯这套配色）。已实现为 `themes/onyx.css`。
- **适用范围**：适合有"涨/跌、好/坏"两极语义的内容。代码扫描报告这类场景里绿色没有合适的用处，所以该报告仍用 Moss 的原配色，严重程度用红、橙、黄、灰四个色相。
- 第一轮曾表示不太喜欢 Moss 的配色，看过 Onyx 后决定在扫描报告里恢复 Moss。Moss 配色具体哪里不满意尚未说明。

## 文字与符号

- **不用间隔号"·"做分隔**（2026-11-23）：浮在行中间的点是很典型的 AI 味。并列的短信息用间距分开，或者拆成独立的行或列。`tools/shot.mjs` 会检查页面文字里是否出现间隔号、项目符号和 emoji。

## 图标

- 不用 emoji 和 Unicode 符号充当图标，统一用内置的 Lucide 图标。
- **大面积重复出现的文字前面不加图标**（2026-11-23）：表格里每一行都有的字段（如"严重程度"一列的阻断、严重、一般、提示）只用文字和颜色，不在前面补图标。同一个图标成列重复会显得很怪。
  - 所有者原话是"什么时候在文字前面补图标是有讲究的，但说不清是什么讲究"。以下是 Claude 的归纳，尚未经所有者确认：图标适合用在页面上只出现一两次、需要被快速找到的东西上（顶栏的仓库和分支、搜索框、外链标记、操作按钮）；不适合用在列表或表格里逐行重复的内容上，那里它不提供新信息，只增加视觉噪音。
